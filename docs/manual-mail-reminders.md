# 手动阶段：邮件 → 事项预览 → Reminders

目标是先让用户核对事项和日期，再写入提醒。没有定时任务、后台监听或自动确认。正文模式每轮最多 8 次模型调用，其余聊天仍为 4 次。

## 1. 阅读邮件并提取事项

```bash
prototype/.venv/bin/python prototype/sdk_demo.py --mail school --mail-body school --no-save
```

`--mail-body` 是单独的正文外发许可，必须是 `--mail` 已开启账户的子集。模型只能读本次启动已经列出的邮件 ID，不能利用旧 Session 中的 ID 越过这个限制。正文只取纯文本，最多 12000 字符；MIME响应最多256 KiB，可能含附件编码，但不会解码或保存附件、打开链接或发送附件给模型。HTML-only 邮件明确返回 no_plain_text，不猜测内容。Himalaya 命令不含 --seen；本机 v2 帮助确认默认读取不改变已读状态。

示例请求：读学校邮箱最近 3 封未读，汇总待办事项、对应时间、时间原文、时区、来源邮件 ID；区分活动开始与提交截止，模糊信息标待确认，不生成提醒。

用户应核对学校所在地时区与自己的时区。邮件发送时间不是事项截止时间。日期缺失时不自动补日期；只有日期时不擅自补具体时刻。

## 2. 复制已确认事项，生成提醒草稿

先本地查看目标清单 ID：

```bash
.aion/bin/aion-reminders lists
prototype/.venv/bin/python prototype/sdk_demo.py --prepare-reminders '<LIST_ID>' --no-save
```

这一步不需要开启邮件读取或提醒读取。可输入 `/paste`，粘贴多行事项，以独立一行 `/end` 结束。告诉 Aion 只为你选定的事项生成草稿。程序将独立打印草稿编号、目标清单、标题、日期、时间/时区和来源，模型不能自行确认。

`prepare_reminder` 只修改本进程的待确认草稿。清单固定在启动授权范围；时间格式为 YYYY-MM-DD 和可选 HH:MM。精确时间必须有 IANA 时区，例如 America/Los_Angeles；无效日期、夏令时重叠/不存在的本地时间会被拒绝并要求澄清。没有日期的事项可以创建为无到期时间任务。

## 3. 人工确认后创建

```text
/drafts
/confirm <草稿编号>
/cancel <草稿编号>
```

只有从终端读到 `/confirm` 才会调用 EventKit 保存；邮件正文、工具结果或模型输出里的同名文本不能触发。模型没有 create/confirm 工具。`/paste` 中的命令文本也只作消息内容，不执行。

确认成功后打印真实保存回执，并加入当前 Session。日期型提醒没有虚构具体时刻；精确时间使用给定时区并设置同一时刻的提醒闹钟。保留简短来源和操作标识用于追溯。不会完成、修改、归档或删除已有提醒。

同一待确认内容会复用草稿；确认编号在执行前即消耗，超时等不确定失败不会自动重试。原生 helper 对同一操作标识顺序重放会查找已有记录以避免重复，但这不是跨进程并发锁或跨会话语义去重。失败后先在 Reminders 核对。草稿仅在内存中，重启不能确认旧草稿编号。

## 验证与边界

67 项 SDK + 20 项 legacy 离线测试通过。原生 helper 编译通过；合成邮件经真实 DeepSeek 调用，完成了正文提取、区分截止/活动时间、生成正确时区草稿，并验证没有写入。真实学校正文外发与测试提醒创建等待本轮单独范围确认，不以合成测试替代实际验收。

## 后续阶段

完成手动阶段真实验收后，再设计已处理邮件标识、跨运行去重、时间歧义处理、失败恢复和审计记录，然后研究定时触发。Aion 在 Mac 本地运行，模型在远端；“模型不在本地”并不意味着只能定时。定时轮询和事件通知是不同的触发方案，都需要可运行的执行环境；目前 EventKit 依赖 Mac。

Codex/ChatGPT Scheduled 可借鉴其定期唤醒和执行记录，但不等于 Agents SDK 已自带调度器。本机项目任务需要机器和应用可运行。本阶段未创建任何调度。
